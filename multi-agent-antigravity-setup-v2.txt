Yes. For what you want, the previous version was still too high-level. You need a **single, detailed “bootstrap specification”** that tells Antigravity exactly how to inspect a project, create the agents, define their responsibilities, coordinate them, parallelize work, isolate changes, test, debug, retry, and report.

One current-platform correction is important: Antigravity 2.0 supports custom agents and asynchronous subagents, with workspace custom agents under `.agents/agents/...`; `/agents` can monitor concurrent agents. Workflows are reusable Markdown procedures invoked with `/workflow-name`. Antigravity also has `/teamwork-preview`, which currently provides managed multi-agent orchestration but is an Ultra-plan preview. ([Google Antigravity][1])

For a reusable system across **any project**, I recommend the controlled setup below rather than depending entirely on the preview teamwork mode.

## What should happen after you paste it

The first run should **not** immediately start coding your application. It should inspect your project and create the orchestration layer.

A healthy result looks roughly like:

```text
Project detected
│
├── Technology detected
├── Architecture detected
├── Test system detected
├── Build system detected
│
├── .ai/
│   ├── project-profile.md
│   ├── task-board.yaml
│   ├── architecture.md
│   ├── project-rules.md
│   └── ...
│
├── .agents/
│   ├── agents/
│   │   ├── lead
│   │   ├── architect
│   │   ├── developer
│   │   ├── qa
│   │   ├── bug-fixer
│   │   ├── security-reviewer
│   │   └── code-reviewer
│   │
│   ├── workflows/
│   └── rules/
│
└── Verification
    └── PASS
```

Antigravity currently recognizes workspace custom agents from `.agents/agents/<name>.md` or `.agents/agents/<name>/agent.md`; custom subagents can then be invoked by the primary agent. ([Google Antigravity][1])

You can inspect/manage the resulting agents through `/agents`, which shows active/completed background subagents and custom-agent selection. ([Google Antigravity][2])

### One thing to enable when available

Antigravity's current managed `/teamwork-preview` can automatically coordinate a multi-agent team, retries, error recovery, and task coordination, but it is currently an Ultra-plan preview. ([Google Antigravity][3])

For your goal of a **reusable setup for every project**, I would keep the custom Lead/worker architecture above as the foundation and use managed teamwork as an optional accelerator rather than making your entire workflow depend on it.

Also, Antigravity Workflows are specifically designed for repeatable multi-step procedures and can be invoked with slash commands, so after the bootstrap you can have commands such as `/autonomous-feature`, `/bug-hunt`, and `/full-verify`. ([Google Antigravity][4])
